## What exists (working in production)

- **Capacity test** `keeper/captest.py`: the ZTE MC889 runs iperf3 itself (vendor object `Device.IP.Diagnostics.Iperf3.`;
  TR-143 download/upload is unusable on MC889 B07). Download 4 streams, upload 1 stream (MC889 gives no UplinkSpeed with 4).
  Servers `37.19.203.1:5201` (Sofia), `169.150.252.2:5201` (Athens) - public, one client at a time, fallback works.
  Slots `01:30,04:30,07:30,12:30,18:30,21:30`, after 10 idle min, never while busy (lock test / night screen / sweep / A/B) or
  < 15 min after a boot. Records `v:2`, `setup` ("LTE anchor|5G cell"), `trigger`.
- **Ceilings** per period = 0.92 x median of the last 5 counted tests (2 needed), capped at plan 200/30. Upload learned
  (`CAPTEST_UP=1` set). Diagnostics (`POST /captest` with any option) never count.
- **Shaper** `keeper/sqm.py`: per 10 s step (cut 15 % on latency while busy, +5 % when clean, idle -> back to ceiling),
  `earn_keep` (useless cuts undone), `climb()` (busy > 75 % at the ceiling with clean latency for 600 s -> x1.05 up to plan;
  latency -> back to learned), `deep_cut()` (3 cuts < 70 % of ceiling in 1 h -> want_test), `reason()` (why text).
- **Triggered tests** `captest.trigger/trig_ok`: setup change held 15 min, climb > +10 %, deep cuts; idle only, >= 1 h after the
  last counted test, none 1 h before a slot, max 6/day. First real one 2026-11-15 08:35 (lock restore 3350/340 -> 100/340). OK.
- **Read-only optional settings** skipped from the TR-143 probe's Writable flags (no more `Mode` 9008 fault);
  `tools/ip3_args.py` dry-runs the iperf3 settings against them.
- **Guard**: a `pending` lock the modem already has -> marked active quietly (no false "still set" alert after the night screen).
- **UI**: ZTE helper panel (`legacy/zte-script-legacy.js`, `keeper_cap_render/keeper_captest/keeper_cap_result`) shows limit /
  ceiling / why / ceiling source / climb / triggers, ceilings per period, last tests, and buttons Test now (counts) /
  Download check / Upload check with live progress. Desktop app bridge `legacy/app/zte_app.py` allows GET + POST `/captest`
  (KEEPER_RUN). DSH plugin `.dsh/plugins/keeper`: actions `captest`, `captest_run kind=count|down|up` (confirm), card lines.
- **API**: `GET /captest` (explain, counted_by_period, climb(s), trigger), `POST /captest[?secs&conn&reverse&server&mode]`,
  `POST/GET /tr069/read?path=`, `/status sqm.now.why`.
