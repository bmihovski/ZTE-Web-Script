# Keeper code review — 2026-11-03 (v2026-11-03f)

Reviewed against docs/BUSINESS_RULES.md. [v] = I confirmed it in the code; others are reported with line + reasoning, worth a glance before fixing.

## CRITICAL — can hang, leave the modem unlocked, abort a test, or auto-apply on the wrong signal

1. **locktest.py:95 `anchor_for`** [v] — `for r in reversed(brain.HIST)` iterates the shared deque with no `list()` snapshot → `RuntimeError: deque mutated during iteration` while the ACS thread appends. It's called at start inside `except ValueError` (does NOT catch RuntimeError), so it aborts the test start. **Fix:** `for r in reversed(list(brain.HIST)):`.

2. **acs.py:84 `wait_informs`** [v] — times out on the WALL clock (`time.time()`), the one spot that isn't monotonic (the module header even says "a clock jump changes nothing"). After a power-cut boot NTP jumps the clock ~hours forward; a jump during the post-boot wait makes the elapsed explode and `wait_informs` return False at once, aborting the lock-test/sweep step exactly in the boot window. **Fix:** use `time.monotonic()` for `t0` and the comparison.

3. **locktest.py finally ~331–441** [v] — the lock *removal* is wrapped in try/except, but the *reporting* that follows (`brain.night_best`/`anchor_best`/`alert.report`/`guard.lock_request`) is not. An exception there propagates out of `finally` and SKIPS the guard re-lock loop (439–441) → the guard lock is never set back to `pending`, so the modem is left unlocked with no re-lock, and the Telegram push is lost. **Fix:** wrap the reporting in its own try/except; run the re-lock loop unconditionally.

4. **brain.py:786 `anchor_best` (LTE) + :798 `anchor_finding`** [v] — the LTE "gain" is `call-ready ≥1pp OR 5G SINR ≥2 OR anchor SINR ≥3` (an OR, with signal terms). This violates quality-first: it can report/auto-apply an LTE lock on a signal-only improvement with no call-ready gain, and the call-ready margin (1pp) is far below the stated 5pp. The `nr` branch correctly uses `clearly_better(quality)`. **Fix:** make the LTE branch use `clearly_better` on the quality vector; let signal only break a quality tie.

## FLAWS — wrong result in edge cases, thread-safety, data quality

5. **brain.py ~669–690** — `REG["lte"]/REG["nr"]` dicts are iterated unsnapshotted (`cells_view`, `network_changes`) while the sampler thread `setdefault`s into them → `dict changed size during iteration`. The deques were fixed; REG was not. **Fix:** iterate `list(REG[..].items())` (or guard REG with a lock).

6. **brain.py ~302,835** — `r["nr_cell"]` indexed directly in `decide`/`report`; `add()` stores `dict(row)` unconditionally, so a sample missing that key raises KeyError in the decision path. **Fix:** `r.get("nr_cell")`.

7. **brain.py ~825,841** — average loss is `mean([f(loss_pct) or 0 ...])`, so minutes with no probe (None→0) count as 0% loss → understated loss, and it contradicts the "never fabricate 0% loss" rule (call-ready's `share()` already excludes empties). **Fix:** drop None before the mean.

8. **brain.py:537 `nr_ca` loop** [v] — skips ARFCN `"0"` but not `"255"`; the primary `nr_cell` path (line 529) skips both. A `255/…` post-boot placeholder from `nr_ca` gets tracked/persisted in `REG["nr"]`. **Fix:** also `continue` on `"255"`.

9. **brain.py ~424 `_reliable_best`** — greedy single pass; the half-minutes gate is computed against the *moving* lead, so a chain of successively smaller pairs can unseat a long-standing one, and the final lead isn't re-checked (clearly_better isn't transitive). Violates "a short lucky pair never overrides a long-standing one". **Fix:** gate challengers against the stable max-minutes leader; after the pass confirm no pair with ≥ half its minutes clearly beats the chosen lead.

10. **brain.py:249 `quality_values`** — missing call-ready sentinel is `-1`, within the 5pp margin of a measured low value, so an unmeasured NR candidate can tie a measured poor one and then win on the SINR/RSRP tie-break. **Fix:** use a strongly-negative sentinel (e.g. -1000).

11. **locktest.py ~495,520** — the NIGHT_RETEST throttle `tested` set counts every row `mode != "cut"`, including not-measured night rows (minutes 0). So a cell that never actually measured is treated as tested and not retried — contradicts "a step that never measured must be retried" (`_dead_cells` correctly requires minutes>0; this set doesn't). **Fix:** exclude `minutes==0` rows from `tested`.

12. **locktest.py ~121** — anchor-switch counting includes blank `lte_cell` (`""`), so one transient blank reading reads as real→""→real = two switches (and drops pin_pct); with `LOCKTEST_MAX_ANCHOR_SWITCHES=0` it false-flags the 5G row `unstable` and drops it from ranking. **Fix:** compute switches over non-empty cells only.

13. **locktest.py ~404** — the winning step's antenna mode is read only from `lt["modes"]` (this run's sweeps). `anchor_best` can return a fresh (<3 h) winner from a *prior* run → no `lt["modes"]` entry → the pair is auto-applied but its measured antenna mode is NOT kept. **Fix:** fall back to `cell_mode(best["lock"])`.

14. **locktest.py ~332,349,421** — the Telegram summary is only pushed on some branches (NR only when best/unstable/failed; LTE only when best/failed; night only when run). A finished test with nothing ranked pushes nothing — violates "push for every finished test". **Fix:** always emit a minimal "finished, nothing ranked" summary.

15. **guard.py ~90–101 `lock_reconcile`** — runs whenever `not busy`, judging from cached `dev.lock_value`. Right after a release's reboot command returns, `busy` clears while the modem is still rebooting with stale lock values showing the old lock → a just-"released" lock can be flipped back to "active", undoing the release. **Fix:** skip reconcile until a lock read is newer than the last lock change (track a change timestamp).

16. **guard.py:68 `lock_do`** — appends the reboot timestamp (spends a `LOCK_MAX_REBOOTS_DAY` slot) before `run()` calls `locks_apply`. If `locks_apply` throws, no reboot happened but the slot is spent → transient failures exhaust the daily cap. **Fix:** record the reboot only after `locks_apply` succeeds.

17. **locks.py ~59 `web_clear`** — posts `REBOOT_DEVICE` before checking the LTE/NR clear results, so a failed clear still reboots the radio and then raises. **Fix:** check results before rebooting.

18. **antennas.py ~82,95 boot apply** — (a) `apply_after_boot` checks the boot generation before acquiring `web_lock`, which a concurrent sweep/web-lock holds ~2 min; a superseded worker then applies a stale mode → re-check generation AFTER acquiring the lock. (b) The two informs of the SAME boot share a generation, so dedupe is by "newer boot supersedes" only — both can pass and apply twice; dedupe by a per-inform boot-id. (c) `apply()` and the sweeps have no try/finally logout → on an exception the keeper stays logged into the ZTE's single web session (locks you/the browser out).

19. **antennas.py ~263** — `sweep_st["running"]` is a non-atomic check-then-set; a scheduled `maybe_sweep` and a manual/lock-test sweep can both pass the guard. **Fix:** test-and-set under a lock.

20. **acs.py ~177 ZTE pin** — only pins when `<ProductClass>` is non-empty; an empty ProductClass is never pinned, so a second ZTE reporting empty PC could mix into the managed data unless `CPE=` is set. **Fix:** fall back to serial/OUI, or warn when PC is empty.

21. **api.py ~201 do_GET** — wraps all errors as 500; client errors raised as `ValueError` (`/export` bad kind, `/lock-tests` bad rat, `/userdata` bad name) return 500 instead of 400, and `repr(e)` leaks internals. The POST path already maps ValueError→400. **Fix:** catch ValueError→400 in do_GET.

22. **api.py ~209 do_POST** — a wrong-method POST to a GET-only route is fed to `acs.serve` (CWMP) instead of returning 405. Benign for the modem, confusing for clients. **Fix:** 405 when the path exists under another method.

23. **deploy.py ~240** — the fresh-sample gate compares the keeper's sample time (router wall clock) against `time.time()` on the deploy host; if the router restarted with an unverified/behind clock, no sample looks "fresh" → auto-rollback of a good deploy. **Fix:** gate on sample count / a "new sample since restart" signal, not two clocks.

24. **sqm.py ~53 `down_on`** — a misformatted `SQM_DOWN_HOURS` raises ValueError in `tick`, caught generically → SQM disabled in 300 s retry loops; also no midnight-wrap (`22:00-06:00` never true). **Fix:** validate/parse once at import; handle `h1>h2` wrap.

25. **store.py ~63 `ago`** — `time.time() - days*86400` for the retention/prune cutoffs is the DST pattern the day-step prune deliberately avoids. **Fix:** `date.today() - timedelta(days=…)`.

## IMPROVEMENTS

26. **common.py log()/raw()** — rotate+append from many threads with no lock → interleaved lines / double-rotate (lost `.1`). Add a log lock.
27. **deploy.py ~206** — `backup()` leaks file handles (open without `with`). Use `with`/`read_bytes`.
28. **common.py ~51,55** — dead `skew is None` branches (handled at :48). Drop them.
29. **locktest.py ~323** — on auto-apply the finally removes all locks (one reboot) then re-locks the winner (more reboots). Defer the removal when an auto-apply will re-lock, to save reboots.
30. **brain.py** — `ts()` is naive-local `.timestamp()` (±1 h across DST); `cells_view` recomputes `best_anchor`/`site_geo` per cell and `report()` re-reads `anchor_ranking()` several times. Cache per call.

## C15 fixed — v2026-11-03i

Reconcile now flips a released/pending lock back to `active` (modem still has it) only when the read is fresh relative to the last keeper change: `lock_do` records `guard["changed_at"]`, and `lock_reconcile` skips the flip while `now < changed_at + LOCK_RECONCILE_SETTLE` (120 s) — the reboot window where the lock read-back is stale. A failed unlock / power-cut leftover (no in-flight keeper change, `changed_at` old) still reconciles immediately. New guard-test case covers the race. 27 of 30 now addressed; deferred: 23 (deploy two-clock), 25 (store DST, negligible), 27 (deploy handles), 29 (reboot-saving reorder).
